## Why

Issue #330 (highest-priority item in the v2.4.0 release plan, #337): `gaze crap --baseline` cannot match a historical absolute-path baseline against current module-relative report paths. Confirmed by an external consumer (complytime/complytime-providers) with Gaze v1.9.0 and v2.3.0.

Root cause, verified in source:

- `internal/crap/analyze.go` (Step 5b, since commit `6fbaafb` "fix: relativize Score.File paths in JSON output") rewrites every `Score.File` to be module-relative before the report is emitted — so baselines generated by older gaze versions carry absolute paths while current reports carry module-relative paths.
- `internal/crap/compare.go` `scoreKey()` matches functions on the literal `s.File + ":" + s.Function`.
- `LoadBaseline` unmarshals the historical path representation verbatim, with no reconciliation against the current report.

Consequences observed in the field: 282 `new_functions`, 191 `removed_functions`, 0 `unchanged`, and 1 false `new_violation` for a function whose body is byte-identical to the merge base (CRAP 72, above the new-function threshold of 30). The command exits 1 on a false failure. Worse, because zero functions match, `regressions: 0` is meaningless — real regressions are invisible. The gate fails in both directions at once: falsely and silently.

This violates Constitution Principle III (Actionable Output: "Metrics MUST be comparable across runs") in practice: a baseline saved by a supported older version of gaze produces garbage when compared by a newer version.

## What Changes

### Baseline path reconciliation

When a baseline is loaded, `gaze crap` reconciles baseline `scores[].file` paths to the canonical module-relative form before `file:function` matching:

- A baseline path that is already relative is untouched.
- An absolute baseline path that lies under the current module directory is rewritten with the same `filepath.Rel(moduleDir, ...)` semantics the report pipeline itself uses (Step 5b) — deterministic, exact, no heuristics.
- An absolute baseline path from a relocated checkout is rewritten against an explicit historical module root supplied by the new `--baseline-root` flag.

No basename or suffix-only matching is introduced (epic #337 Phase 1 rule): two files with the same basename in different packages remain distinct because the full path prefix must match the module root.

### Actionable incompatibility diagnostic

A baseline entry whose absolute path can be reconciled by neither the current module directory nor `--baseline-root` makes the comparison fail loudly with an error that names the baseline file, the count of unreconcilable entries, an example path, and the two remediations (regenerate the baseline, or pass `--baseline-root`). This is a hard error in both `--baseline` (explicit) and auto-detected modes — a documented deviation from the existing silent-skip rule for unparseable auto-detected baselines, because silently skipping a parseable-but-incompatible baseline would turn a false failure into a silent false pass, weakening a governance gate.

### Preserved semantics

Reconciliation rewrites only the `File` field used for matching. CRAP/GazeCRAP values, epsilon, new-function thresholds, status classification, pass/fail logic, exit codes, and the comparison JSON schema are unchanged. A module-relative baseline (the normal case) produces byte-identical behavior: zero reconciliation, zero output change.

### Observability

- A one-line stderr notice reports how many absolute paths were normalized and recommends regenerating the baseline.
- A stderr warning fires when reconciliation occurred but zero baseline entries matched any current entry — the signature of a wrong `--baseline-root`.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `baseline`: baseline loading gains path reconciliation before `file:function` matching; incompatible baselines fail with an actionable diagnostic instead of misclassifying every entry as new/removed; new `--baseline-root` flag supplies a historical module root for relocated checkouts.
- `gaze crap`: new optional `--baseline-root <dir>` flag (inert when no baseline is loaded or the baseline is already module-relative).

### Removed Capabilities

- None.

## Impact

### Files Modified

- `internal/crap/` — new reconciliation logic (pure function, separate from `LoadBaseline` deserialization and `Compare` matching), plus tests
- `cmd/gaze/main.go` — `--baseline-root` flag, wiring through `runCrap` params → `resolveBaselineAndCompare` → `loadAndCompare`, notice/warning output
- `docs/reference/cli/crap.md` — flag table and reconciliation behavior
- `docs/guides/ci-integration.md` — baseline migration guidance for historical absolute-path baselines
- `README.md` — baseline section note
- Website documentation issue in `unbound-force/website` (new user-facing flag; precedent #150 for the original `--baseline` flag)

### External Impact

- Consumers with committed historical absolute-path baselines (the reproducing complytime baseline has not been rewritten) get a working comparison without touching the committed file when the checkout path matches the baseline's root, and a clear migration path (`--baseline-root`) or actionable error otherwise.
- All existing module-relative baselines: zero behavior change.

### Backward Compatibility

- Comparison JSON output: unchanged schema, no new fields (diagnostics go to stderr).
- Exit codes: unchanged for compatible baselines. The new incompatibility error path only affects configurations that are broken today (exit 1 with false violations); those now exit non-zero with a truthful diagnostic.
- No new flags on existing flag semantics; `--baseline-root` defaults to empty (feature off).

## Constitution Alignment

Assessed against the Gaze constitution v1.3.0 (`.specify/memory/constitution.md`).

### I. Accuracy

**Assessment**: PASS

The change restores accurate comparison of observable outcomes: the phantom `new_violation` false positive (CRAP 72 on a byte-identical function in #330) and the invisible-regression false negative (0 `unchanged` masking real regressions) are eliminated by deterministic path reconciliation. After reconciliation every reported `new_violation` corresponds to a real complexity regression; no trusted metric is fabricated. Accuracy is backed by named regression tests covering the absolute vs module-relative same-function case.

### II. Minimal Assumptions

**Assessment**: PASS

The fix requires no annotation or restructuring of host projects: baselines generated by older gaze versions are reconciled automatically in the same checkout using `filepath.Rel` against the current module directory. No test-framework, language, or coding-style assumptions are added; supported environments are unchanged. The explicit `--baseline-root` assumption for relocated checkouts is documented and enforced at the CLI entry point — missing or wrong roots fail loudly with remediation rather than being silently ignored.

### III. Actionable Output

**Assessment**: PASS

Every output guides concrete remediation: the incompatibility diagnostic names the baseline file, the count of unreconcilable entries, an example path, and both remediations (regenerate or `--baseline-root`). Metrics remain comparable across runs (constitution mandate) because the same `file:function` now matches itself across gaze versions. Both human-readable stderr diagnostics and machine-readable JSON (unchanged schema) are preserved.

### IV. Testability

**Assessment**: PASS

Reconciliation is a deterministic, no-I/O, in-place normalization of a freshly loaded `Report` value per R5 contract — testable in isolation with synthetic `Report` values without external services or shared mutable state. Coverage strategy is specified in `tasks.md` (Phase 1 unit tests plus Phase 2 five epic-mandated regression cases: absolute vs module-relative same function; same basename/function in several files; relocated checkout; real new/removed functions; unchanged score above the new-function threshold), each as a named test; coverage ratchets will treat regression as failure.
